## 1. المشروع باختصار

منصة عربية لحفظ القرآن وفهمه: مصحف، حفظ، تسميع بالصوت، مراجعة متباعدة، قصص ومرئيات، ومساعد ذكي مقيّد بالمصادر.

| الطبقة | التقنية |
|---|---|
| الواجهة والخادم | Next.js 15.5 (App Router) + React 19 + Tailwind 4 — الـ backend هو route handlers داخل `src/app/api/v1/*` |
| قاعدة البيانات | PostgreSQL على **Neon** (منطقة us-east-2) عبر Prisma 6 — مع امتداد `vector` |
| تسجيل الدخول | **Clerk** (Google + بريد إلكتروني) — `@clerk/nextjs` v7 (Core 3) |
| الاستضافة | **Vercel** — https://modaker-zeta.vercel.app (الدوال في iad1 بجوار قاعدة البيانات) |
| الكود | GitHub: `manar103/modaker` فرع `main` |
| الاختبارات | `npm test` (node:test عبر tsx) — **436 اختبارًا ناجحًا** · `npx tsc --noEmit` نظيف · `npx next build` ينجح |

ملفات مرجعية مهمة: `docs/ARCHITECTURE*.md` (التصميم وقواعد الأمان الديني)، `.env.example` (كل المتغيرات مشروحة).

## 2. طريقة العمل مع صاحبة المشروع (مهم جدًا)

- **اللغة:** تكتب بالعامية المصرية، والردّ بالعربية الفصحى المبسّطة. المصطلحات التقنية بالإنجليزية بين علامات الكود.
- **خطوة بخطوة:** في المهام الطويلة (نشر، إعداد خدمات) أعطِ خطوة واحدة واضحة، ثم انتظر حتى تقول «خلصت».
- **أوامر git تنفذها هي بنفسها:** لا تعمل `commit` ولا `push` بنفسك. أعطها الأوامر في كتل ```` ```bash ```` منفصلة (`git add -A` ثم `git status --short` للمراجعة ثم `git commit -m "…"` ثم `git push origin main`). يمكنك تجهيز الـ merge وحلّ التعارضات محليًا، ثم تعطيها أمر الدفع.
- **الأسرار:** أي مفتاح أو كلمة مرور تضعه هي في `.env` بنفسها — **لا تطلب لصقه في الشات**. افحص وجود القيم فقط (`<set>/<empty>`) دون طباعتها. `.env` مُستثنى من git.
- **لا تخترع:** لا روابط ولا معرّفات ولا مدد ولا عناوين. كل معلومة خارجية (يوتيوب، قرّاء، خطوط) تُجلب من مصدرها وتُتحقق (مثلًا: طلب HEAD لملفات الصوت، oEmbed لعناوين يوتيوب).
- **تحقّق قبل أن تقول «تمّ»:** شغّل الاختبارات والـ typecheck، وجرّب في المتصفح، وقل بصراحة ما لم يُختبر.
- **لا تلمس خادمها الشخصي:** غالبًا يكون عندها `npm run dev` أو `npm run start` على المنفذ 3000. الخادمان يشتركان في مجلد `.next`، فلا تشغّل build/dev على نفس المجلد وهو يعمل. للاختبار استخدم نسخة منفصلة (`git worktree` على نفس القرص H: مع junction لـ `node_modules`) على منفذ آخر، ثم احذفها.
- **لا تنشئ حسابات على خدمات خارجية بنفسك** (Clerk، OpenAI…). اطلب منها تسجيل الدخول، أو اختبر ما لا يحتاج حسابًا.

## 3. قواعد المحتوى الديني (مفروضة في الكود والاختبارات)

- **لا نصّ قرآني داخل المستودع.** النص يأتي فقط من مزوّد موثّق (`src/server/quran/*`، افتراضيًا Quran.com) ويُتحقق منه بـ checksum. الاختبارات تستخدم نصًا عربيًا اصطناعيًا (`tests/_fixtures.ts`).
- المساعد لا يُفتي، ولا ينقل حديثًا من الذاكرة، ويمتنع حين لا توجد مادة موثوقة («لا تتوفر لدي مادة موثوقة كافية…»). **إجابة خاطئة أسوأ من عدم الإجابة.**
- المحتوى المعروض (قصص/فيديوهات) له حالة مراجعة (`isDemo`/`reviewState`) — راجع `docs/ARCHITECTURE-safety.md` والاختبارات قبل تغييرها.
- اختبار `tests/stories-restoration.test.ts` يشترط أن `STORY_RANGES` يطابق قصص الموقع **تمامًا** — أي أسماء مواضع إضافية تُضاف في `src/server/rag/named-passages.ts`.

## 5. الحالة الحالية — أين توقفنا

**النشر على Vercel تمّ، لكن تسجيل الدخول لا يظهر بعد.** الموقع يعرض «تسجيل الدخول… غير مفعّلين على هذا الخادم».

السبب (مُشخّص من الموقع الحي): الخادم يرى مفاتيح Clerk (الاستجابة فيها `X-Clerk-Auth-Status`) وقاعدة البيانات متصلة (`/api/v1/me` ⇒ 401)، لكن `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` **غير موجود في كود المتصفح** — لأن متغيرات `NEXT_PUBLIC_*` تُضمَّن وقت البناء، والبناء الحالي تمّ قبل حفظ المتغيرات.

**الخطوة التالية مباشرة:**
1. التأكد أن المتغيرات مضافة لبيئة **Production** في Vercel، وإضافة `NEXT_PUBLIC_APP_URL=https://modaker-zeta.vercel.app`.
2. **Redeploy** مع إلغاء «Use existing build cache».
3. التحقق: `curl https://modaker-zeta.vercel.app/login` ثم البحث في ملفات `/_next/static/chunks/*.js` عن `pk_test_` (يجب أن يظهر)، ثم تجربة الدخول على الموقع الحي.

## 6. المهام القادمة (بالأولوية)

1. **إنهاء النشر** (القسم 5) واختبار الدخول بـ Google والبريد على الموقع الحي، والتأكد أن صف `User` يُنشأ في Neon.
2. **مفتاح OpenAI للشات بوت:** إضافة `OPENAI_API_KEY` و`ASSISTANT_WEB_SEARCH=on`، ثم اختبار الأسئلة الممتنعة (أركان الإسلام، فضل سورة الملك، سبب تسمية الكهف). تنبيه: بوابة الويب (`src/server/safety/web-gate.ts`) مقصودة أن تكون ضيقة (أسئلة تاريخ/سيرة/أعلام/مصطلحات فقط) — أي توسيع لها قرار يُناقش معها أولًا. المفتاح نفسه يُفعّل افتراضيًا ميزات مدفوعة: `ASSISTANT_TTS` و`COACH_AI` (لكل منها حدّ يومي) — يمكن إيقافهما بـ `off`.
3. **Clerk للإنتاج:** مفاتيح التطوير تعمل على `vercel.app` مع شارة «Development mode». الانتقال لمفاتيح الإنتاج يحتاج نطاقًا خاصًا (مثل modaker.com) + بيانات Google OAuth خاصة بها في لوحة Clerk. اسم التطبيق في Clerk حاليًا «MODaker» — تغييره من لوحة Clerk.
4. **التذكيرات المجدولة (اختياري):** `POST /api/v1/cron/reminders` يحتاج `CRON_SECRET` + Vercel Cron (وقد تحتاج `NEXT_PUBLIC_VAPID_PUBLIC_KEY`/`VAPID_PRIVATE_KEY` للإشعارات).

## 7. ملاحظات ومخاطر معروفة

- **واجهة qdc** (تخطيط المصحف) غير موثّقة رسميًا — إن تغيّرت، التحقق سيرفض الصفحات بدل عرض خطأ. رخصة خطوط مجمع الملك فهد لم تُراجع رسميًا بعد (`docs/QURAN-SOURCE-MIGRATION-PLAN.md`)؛ الخطوط تُحمَّل من CDN الخاص بـ Quran.com.
- **Neon المجاني** ينام بعد 5 دقائق خمول؛ أول طلب بعده يتأخر ~1–3 ثوانٍ.
- **محدِّد الطلبات (rate limiter)** في الذاكرة لكل instance — على Vercel كل instance له عدّاده. ويعتمد على `X-Forwarded-For` (مناسب خلف Vercel).
- `npm run dev` بطيء في أول فتح لكل صفحة (تجميع) — هذا طبيعي؛ نسخة الإنتاج أسرع بمئات المرات.
- **محتوى الفيديوهات:** بعض عناوين اليوتيوب فيها ادعاءات خارج النص القرآني وتحتاج مراجعة شرعية.

## 8. خبرات عملية على هذا الجهاز (Windows + Git Bash)

- الـ heredoc في Git Bash يفشل أحيانًا مع علامات الاقتباس المتداخلة؛ الأسلم كتابة سكربت Python في ملف (scratchpad) ثم تشغيله. استخدم `PYTHONIOENCODING=utf-8` عند طباعة عربي.
- أداة التحرير تحوّل `\uXXXX` داخل النص إلى الحرف نفسه؛ لكتابة محارف غير مرئية في الكود استخدم `String.fromCharCode(0x…)`.
- `prisma generate` يفشل بـ `EPERM` إن كان خادم Next يعمل ويقفل ملف المحرك — أوقف الخادم أولًا.
- بعد حذف routes امسح `.next` قبل `tsc` (أنواع قديمة مولّدة).
- Quran.com يرفض User-Agent الافتراضي لـ Python (403) — استخدم `curl`.
- قاعدة بيانات تجريبية مؤقتة: PGlite + `@electric-sql/pglite-socket` في الـ scratchpad (مع `maxConnections` و`pgbouncer=true` في الرابط)، ولا تكتب رابطها في ملفات المشروع — مرّره للخادم عبر متغيرات العملية فقط.
- لا تثق بـ `total_records` من Quran.com (يحسب صفوف الترويسات)؛ تحقّق من تتابع الآيات بدلًا منه.
